# 모임콕 (가칭)

동아리·학생회용 일정 투표 + AI 공지문 자동 작성 웹앱.
링크 하나로 가능한 시간을 모으고, 겹치는 시간을 보고 일정을 확정하면 공지문 초안까지 만들어 줍니다.

## 실행

1. [Supabase](https://supabase.com)에서 프로젝트를 만든다
2. 대시보드 **SQL Editor**에 `supabase/schema.sql` 전체를 붙여 넣고 실행한다 (기능이 추가되면 최신 파일로 다시 실행하면 된다. 기존 데이터는 그대로 남는다)
3. `.env.example`을 `.env`로 복사하고, **Project Settings → API**의 URL과 anon(public) 키를 넣는다
4. (공지문 기능) [Anthropic Console](https://console.anthropic.com)에서 API 키를 발급받아 `.env`의 `ANTHROPIC_API_KEY`에 넣는다. 키가 없어도 나머지 기능은 동작한다
5. 실행

```bash
npm install
bash supabase/check-rls.sh   # 권한 점검: "실패 0"이 나와야 함
npm run dev
```

## 현재 상태

- 행사 생성, 투표(시간 칸 드래그), 같은 이름으로 응답 수정
- Supabase 저장: 새로고침·다른 기기에서도 링크가 열림
- 관리 화면: 응답자 명단, 많이 겹치는 시간 TOP 3, 시간별 가능 인원 히트맵
- 일정 확정: 추천 시간을 누르거나 히트맵에서 범위를 끌어 고른 뒤 확정·변경·취소. 참여자 화면에 확정 배너 표시
- 공지문 쓰기: 확정 후 말투(정기모임 / MT·행사 / 공식 공지)와 추가 내용을 고르면 Claude가 단톡방 공지 초안을 써 준다. 응답 현황은 숫자로만 넣고 안 되는 사람 이름은 넣지 않는다

## 보안 설계 요약

- 세 테이블 모두 RLS를 켜고 정책을 두지 않아, 공개 anon 키로는 테이블을 직접 읽거나 쓸 수 없다
- 데이터 접근은 RPC 함수로만 한다. 행사 ID를 아는 사람만 그 행사를 볼 수 있다
- 관리키는 별도 테이블에 두고, 관리 작업은 함수 안에서 키를 검사한다
- 슬롯은 DB에서 다시 검증한다 (형식, 행사 날짜·시간 범위, 30분 단위, 중복 제거, 전체 칸 수 상한)
- Claude API 키는 서버 함수(`api/notice.js`)에만 있다. 함수는 Claude를 부르기 전에 관리키부터 확인한다

## 알려진 한계

- **이름이 곧 식별자**: 다른 사람이 내 이름으로 응답하면 내 응답을 덮어쓸 수 있다 (로그인 없는 구조의 트레이드오프)
- **관리 링크 분실 시 복구 불가**: 관리키는 만든 기기의 브라우저에만 저장된다
- **관리키 평문 저장**: RLS와 권한 회수로 막혀 있지만 해시 저장은 하지 않았다
- **행사 생성 횟수 제한 없음**: 누구나 행사를 무한히 만들 수 있다 (스팸 방지 없음)
- **실시간 갱신 없음**: 다른 사람의 응답은 새로고침해야 보인다
- **응답 삭제 기능 없음**
- **공지문 호출 횟수 제한 없음**: 관리 링크를 가진 사람은 공지문을 계속 다시 만들 수 있다 (API 비용)
- **공지문은 초안**: AI가 쓴 글이라 올리기 전에 운영진이 읽고 고쳐야 한다
- **확정은 하루 안의 연속 구간만**: 이틀 이상에 걸친 일정(예: 1박 2일 MT)은 첫날 시간대로 확정해야 한다
